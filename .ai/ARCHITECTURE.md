# LinuxToys: adapted architecture map

Updated 2026-11-12 for the bounded U1 source patch. Baseline is M4B
`8d8ced68cb58c8d74598b97144a3731c6d12078b`, whose tree
`cbe4f4aa8292b36a51613597ab9e66a6ec721d4c` also belongs to `a7ed93bb`.
Selected upstream source: `7d291e3ac54f67e57ddc0a9a58a6fb381c37e1cc` in
`target/upstream-7.10.1-review/repository.git`. This map describes the local
implementation; upstream's broader refactor is not adopted.

## Entry points and runtime

`p3/linuxtoys.py` sets up the source/vendor paths and enters `app.main`.
The GTK GUI uses `window.py`, the Textual TUI lives under `app/tui`, and
`easy_cli.py` dispatches headless operations. `library_loader.py` supports both
package imports and direct-file nested execution. U1 leaves that module intact.
The CLI confirmation function treats EOF and Ctrl+C as cancellation; existing
batch continuation decisions are retained, including the distinct exit-1 branch.

Catalog ownership remains in `parser.py`, `repo_parser.py`, `appstream_cache.py`
and source-specific catalog modules. Native catalog parsing is provided by
`src/catalog-rs`; GTK helpers in `src/gui-rs` expose the existing ctypes ABI via
`gui_rs.py`. U1 changes no Rust code, exported APIs, catalog composition or native
qualification claims.

## U1 persistence and reporting

`atomic_io.py` provides bytes/text/JSON writers using a unique `mkstemp` sibling
and `os.replace`. Optional mode and file fsync are applied before publication;
encoding and JSON options belong to each caller. Default staging permissions are
0600, even over an existing file. Callers must explicitly review mode semantics
before migration. Cleanup on ordinary failure is best effort; crashes can leave
staging files. The helper does not fsync directories or lock read-modify-write
transactions.

Only two writers use it in U1:

- `homebrew_catalog.load_or_refresh`: preserves the raw validated formula bytes,
  0600 mode, file fsync, source-presence checks, lock, warning and cached fallback.
- `antenna.antenna._save_history`: preserves default JSON serialization, 0700
  cache directory, 0600 file, last-ten-history caller behavior and silent failure.
  Token/bootstrap caches and reporting authentication are unchanged.

Homebrew popularity remains on its existing writer, including its exceptional
cleanup behavior. Settings, translation caches, other catalogs and script
materialization are not migrated.

`term_runner.on_child_exit` records the decoded child exit code for reporting.
`term_reporting.py` prefers VTE's absolute buffer range (cursor row plus viewport
height), accepts both string and tuple bindings and retains existing clipboard
and captured-log fallbacks. It does not adopt upstream's 200-line cap or clipboard
removal. Exit 100 prevents manual/automatic cancellation reports; manual sending
still requires the existing confirmation, and automatic reports retain their
existing opt-in setting.

`antenna/antenna.py` imports AppStream transcripts from the parent app package and
prepends them so terminal failure output stays last. Local empty reports retain
their existing suppression; HTTP 422 validation errors naming the logs field are
surfaced as `EmptyReportError` and shown as an empty-report explanation by the
terminal UI. Other HTTP errors retain failure handling. This does not establish
client-side secret redaction or any guarantee about the reporting server.

## Verification and qualification boundary

`dev/tests/test_atomic_io.py` and `test_u1_reporting.py` use temporary files and
fake HTTP/GI/native/process dependencies. See `dev/U1-IMPLEMENTATION.md` for exact
scope, test selection, preservation results and deferred work. No live report,
package installation, application build, VM or service operation is part of U1.

M4A's original artifact SHA-256 remains
`83173db3b42d8ef966b6bde02f064beb42ee71b4593bfd727a3fefefdb862f04`.
M1–M4B historical source IDs, evidence, VM recovery references and cold-launch
limitations remain historical facts. The U1 working tree is uncommitted and has
no newly qualified native artifact. Native AArch64 rebuild/runtime/VTE/DEB/VM
checks require a later authorized phase. Native AMD64 support is not inferred
from fixtures or emulation; declared minimum-language-version execution also
remains unqualified.

During final U1 preservation checks, a concurrent attribution operation changed
HEAD to `0f516736477449f05040cd92bf3f47773cf87041` with the same baseline tree,
updated milestone branch refs and changed two ignored M4B evidence files. U1 did
not perform or repair that operation. Full history/evidence preservation is a
failed review gate; the detailed before/after record is in the implementation
report and `target/u1-implementation/preservation.json`.
